# 第1部 作品における AI の活用

## 1. 短縮版（フォーム貼り付け用・約 300 字）

試験問題の生成に Amazon Bedrock の Converse API を使っています。図表や板書を落とさないため、資料は PDF や画像のまま渡し、テキスト抽出はしません。

設計の中心は「AI に任せることと任せないこと」の線引きです。文章を書く仕事だけをモデルに渡し、出題数の配分、選択肢の並び順、採点の閾値、出力の検証はコード側で行います。生成 AI の出力は外部入力とみなして境界で検証し、成立しない問題は捨て、壊れた JSON は復元します。

用途ごとにモデルを分け、作問には Claude Sonnet 5、採点と解説には安価な GLM-5 を使いコストを抑えています。

## 2. 用途ごとの使い方

### 2.1 作問（Claude Sonnet 5）

資料を **Converse API の document / image ブロックにそのまま載せて**渡す。

```
document: PDF, Word, Excel, HTML, txt, md
image:    PNG, JPEG, GIF, WebP
```

テキスト抽出ライブラリを挟まない理由は、図表・数式・板書の写真といった
「テキストにすると失われる情報」が授業資料の要点になりやすいため。
スキャンした資料もモデルが画像として読める範囲で扱える。

Bedrock の制約への対応として、document の name に日本語が使えないため
`material 1` などに置き換え、`material 1 = 「〇〇.pdf」` という対応表を
プロンプト本文に書いてモデルに参照させている。

**プロンプトで定義していること**（`server/src/prompts.ts`）

- 資料の記述だけを根拠にし、資料外の知識を要する問題を作らせない
- 出題しない対象を列挙：表紙・目次・ページ番号・著作権表記、導入の小話や体験談、
  例題に出てくる固有の数値や人名、授業運営に関する記述（提出期限・配点・参考文献）
- 形式ごとの制約：5択はちょうど5つで正解1つ・「すべて正しい」「該当なし」は禁止、
  複数選択は正解2〜4つで個数を問題文に書かない、
  穴埋めは解答が一意に定まる語だけを空欄にする、
  コードは必ずフェンスで囲み言語名を付ける
- **難易度の定義とルーブリック** — ここが特に踏み込んだ部分（後述）

### 2.2 記述解答の採点（GLM-5）

模範解答と採点観点（`keyPoints`）と比較し、0〜100 点の部分点と
日本語のフィードバックを構造化出力で返させる。

- 表現の違い・語順・同義語では減点しない、と明示
- 模範解答と矛盾する記述は減点する
- 空欄や無関係な解答は 0 点

**合否の閾値はコード側**で決める（80 以上を correct、40〜79 を partial、39 以下を incorrect）。
モデルに「合格かどうか」を判断させず、点数だけを出させて線引きは実装で持つ。

### 2.3 解説の生成（GLM-5）

間違えた問題について、なぜその答えになるかを平文で生成する。
一度生成したものは DB に保存し、再表示では再生成しない（再課金しない）。

### 2.4 モデルを使い分けた理由

| 役割 | 要求される能力 | 採用 |
|---|---|---|
| 作問 | PDF・画像を**直接読む** | Claude Sonnet 5 |
| 採点 | テキスト処理 + 構造化出力 | GLM-5（安価） |
| 解説 | テキスト処理のみ | GLM-5（安価） |

資料を読む必要があるのは作問だけ。採点と解説はテキストしか扱わないので、
高価なモデルを使う理由がない。管理画面から役割ごとに切り替えられる。

## 3. AI に任せなかったこと

作品の性格を決めているのはこの部分。

| 項目 | 実装 | AI に任せない理由 |
|---|---|---|
| 出題数の配分 | 最大剰余法で整数配分（`plan.ts`） | 割合の計算が最も雑になる。合計が 24 問や 26 問になる |
| 選択肢の並び順 | Fisher-Yates シャッフル | 正解が A・B に偏る。慣れると読まずに当てられる |
| 採点の閾値 | 定数で持つ | 判定基準が回ごとに揺れてはいけない |
| 穴埋めの照合 | NFKC 正規化 + 文字列比較（**AI 不使用**） | 一意に定まる答えの照合に確率的な判断は不要 |
| 出力の妥当性 | 1 問ずつ検査して捨てる | スキーマを満たしても問題として成立しないことがある |

穴埋めの正規化では、全角/半角・大文字小文字・空白・括弧や句読点の差は吸収するが、
**送り仮名や漢字とかなの違いは吸収しない**。正規化しすぎると別の語を正解にしてしまうため、
そこは「許容表記をモデルに複数列挙させ、先頭を代表表記とする」方針に分けた。

## 4. AI の不確実性にどう対処したか

生成 AI を組み込むうえで実際に起きた問題と、その対処。

| 起きたこと | 対処 |
|---|---|
| 自由文の JSON が壊れる | tool use で JSON Schema を宣言し `toolChoice` で強制 |
| モデルによって受け付けない指定がある | `temperature` や `toolChoice` を外して再試行し、制約をモデル単位で記憶 |
| スキーマは通るが問題として成立しない | 検証層で 1 問ずつ検査し、捨てた理由をすべてログに残す |
| 値に後続キーを巻き込んで文字列化する | キー名を付け直して再パースする復元処理を実装 |
| 出力が途中で切れる | 完結している要素だけを拾う salvage 処理 |
| 生成に約 70 秒かかる | 非同期ジョブ化。202 で受け付けて後ろで処理する |
| AI 側の混雑で 503 が続く | 一時的失敗だけ再試行（指数バックオフ）し、代替モデルへ切り替え |
| 使えないモデルへの誤設定 | 管理画面の候補を運用者が確認したものだけに限定 |
| コストが読めない | モデルごとに単価を持ち、使用履歴の行ごとに計算して合算 |

「LLM の出力をネットワーク越しの外部入力と同じ扱いにする」という方針に統一したことで、
どこで検証すべきかが機械的に決まり、設計の見通しがよくなった。

## 5. 問題の質そのものへの踏み込み

単に「問題を作らせる」のではなく、**悪い難しさを禁止する**指示を入れた。

難易度は「問う内容の難しさ」だけで表現させ、次を明示的に禁止している。

- 出題形式を変えること（難しくしたいから記述問題にする）
- 問題文・選択肢の文章を長くすること（読解量は難易度ではない）
- 解答に必要な文字数や空欄の数を増やすこと
- わざと紛らわしい言い回しや否定の入れ子を使うこと

そのうえで、形式ごとに「正しい難しくし方」を指示している。
たとえば5択の hard は、用語と定義の対応を問うのをやめ、
条件を変えたときの帰結・因果の向き・適用範囲の境界を問わせる。
誤答は「正しい知識だが問われている条件には当てはまらないもの」「因果を逆にしたもの」
「別の概念の定義」から作らせ、選択肢の長さは正解も誤答も揃えさせる。

AI は放っておくと「長くすれば難しい」という方向に流れる。
そこを言語化して抑えたことが、実用に足る問題が出るかどうかの分かれ目だった。

## AI アシスタントとの作業で実施した内容（記録が残っているもの）

以下は 2026 年 8 月 31 日のセッションで実際に行われた作業。

**1. 障害の切り分け**

Bedrock で作問が失敗する原因の調査。API キーの有効性、モデルアクセス、
リージョンの状態を切り分け、`us.anthropic.claude-sonnet-5` が 14 回中 12 回
`503` を返していることを実測で特定。`global.` 接頭辞のプロファイルは
5 回中 5 回成功したため、AWS 側のキャパシティ不足と結論付けた。

**2. 可用性の実装**

一時的失敗の判定、指数バックオフ + ジッタによる再試行、代替モデルへの
フォールバックを `bedrock.ts` に実装。実際に 503 を返すモデルを本命に据えた状態で
動作を検証し、再試行で成功する場合とフォールバックする場合の両方を確認した。

**3. 不具合の原因特定と修正**

「生成が失敗する」「クイズ名が汎用の文言になる」という別々に見えた 2 件が、
モデルが `questions` の値に `title` を巻き込んで文字列化する同一原因だったことを特定。
復元処理とタイトルの整形・代替処理を実装し、壊れ方を再現した 22 件のケースで検証した。

**4. 機能追加**

管理画面からのアカウント作成機能。サーバ側のエンドポイント、入力検証、
プラン割り当て、フロントのフォームまで。権限昇格の経路を作らないよう
`role` を `user` に固定。ローカルに API を立てて 20 件のケースで検証した。

**5. ドキュメント作成**

`docs/how-it-was-built.md`、`docs/overview.md`、および本ファイル。

**6. 紹介動画の編集**

`ffmpeg` による機械的な編集（無音区間の検出、27.6 秒の静止区間を 8 倍速に圧縮、
テロップとタイトルカードの焼き込み、2 分 33 秒 → 1 分 50 秒）。
映像の内容判断はフレームを抽出して静止画として確認する形で行った。
